What does “screening” mean?

It is a preselection step that avoids rebuilding the case blindly. The GPU model calculates a plausible maximum-temperature interval for each change. A 77.0–79.1 °C range means the peak should land inside it only if the assumed airflow improvement is real.

Reference: the model reproduces an 80.3 °C peak for the present configuration. New-configuration values are not measurements and are not CFD results.

EXPERIMENT → MODEL → DECISION TRACEABLE EVIDENCE CHAIN
01Calibration

One declared dataset is used to estimate model parameters. Good calibration fit only proves that the model can reproduce data it has already seen.

02Verification

We check that the implementation behaves as intended: stable equations, positive thermal parameters, correct units, synchronisation and no accidental use of reserved data.

03Validation

A different physical experiment is predicted without refitting. FIT scores curve shape; RMSE reports the typical temperature error in degrees Celsius.

04Authority

The validation result determines what the model may be used for: prediction, preliminary screening or diagnosis only.

WHY THE CPU MODEL IS NOT ACCEPTED YET37.3% FIT · 4.51 °C RMSE

The CPU-only step identified a fast silicon response and a slower cooler/case response. Under combined load, however, the GPU changes the shared-air temperature while the motherboard fan controls also move. With no measured internal-air state, the model cannot distinguish all of those effects.

What it taught us: CPU power alone is not a sufficient input. The existing CPU fan-to-grille guide was installed throughout every recorded test, so its effect is already embedded in the baseline and cannot be isolated from these data. We need independent CPU-fan excitation, a repeated combined test and—later—one intake-air or case-air temperature channel to make the shared thermal state observable.

WHAT THE MIMO MODEL TAUGHT USCPU 47.1% FIT · GPU 9.6% FIT

The coupled model used CPU power, GPU power and available fan signals as multiple inputs, with CPU and GPU temperatures as multiple outputs. It attempted to learn cross-heating in both directions.

Why it failed validation: CPU and GPU inputs moved together for too much of the campaign, fan telemetry was incomplete, and no shared-air temperature was measured. The model could fit correlation but not identify causation. That is a useful result because it tells us exactly which experiments are missing.

NEXT STEPSFROM DEMONSTRATOR TO INTEGRATION STUDY
  1. 01
    Close the geometry

    Measure the exact PSU and cooler models, fan diameters/thicknesses, fan-to-panel gaps, CPU-guide inlet/length/sealing, GPU clearances, cable blockage, grille open area and the real desk plenum.

  2. 02
    Qualify the baseline

    Run at least three baseline repetitions with identical idle, load and cool-down phases. Record power, every valid RPM channel and the 26.5 °C ambient assumption.

  3. 03
    Run the most informative test

    First step GPU fan command at near-constant GPU power; then run baseline → removable sealed GPU guide → baseline, ideally three repetitions per state.

  4. 04
    Re-identify and validate

    Refit without using the validation runs. Confirm that measured peaks, time constants and the A/B temperature change fall inside the predicted interval.

CFD ENTRY CRITERIAWHEN THE MODEL IS READY
  • Three-run peak repeatability within about ±1 °C.
  • Independent GPU validation below 2 °C RMSE while retaining strong transient FIT.
  • CPU model validated on both CPU-only and combined load, preferably below 3 °C RMSE.
  • Fan RPM/curve or measured flow estimates, grille pressure-loss assumptions and all opening areas documented.
  • Fan/duct gaps measured to a few millimetres and electrical heat sources reconciled with the energy balance.
WHAT CFD WILL ANSWERSPATIAL QUESTIONS
  • Where hot air recirculates and which component ingests it.
  • Whether top or bottom external fans create useful through-flow or merely short-circuit an intake.
  • How a sealed guide, cable obstruction or fan spacing changes local velocity and inlet temperature.
  • Which fan orientation is worth a physical rebuild and where a temperature-sensitive component could safely sit.
WHY THIS MATTERS FOR POWERPLANTTRANSFERABLE WORKFLOW
  • Configuration-controlled geometry and explicit uncertainty.
  • Measured boundary conditions instead of invented precision.
  • Reduced-order transient models for rapid screening.
  • CFD reserved for spatial flow questions and validated against tests.
  • A traceable accept/reject decision chain analogous to engine–nacelle thermal integration.
